# moveit_controllers.yaml: match the robot's action servers

**TL;DR** MoveIt's simple controller manager connects to one action server per controller: **`/<controller name>/<action_ns>`**. Each name and type in `config/moveit_controllers.yaml` must match what `ros2 action list` / `ros2 action info -t` show, or MoveIt plans but cannot execute.

## Final file (course robot)
```yaml
# MoveIt uses this configuration for controller management

moveit_controller_manager: moveit_simple_controller_manager/MoveItSimpleControllerManager

moveit_simple_controller_manager:
  controller_names:
    - joint_trajectory_controller
    - gripper_controller

  joint_trajectory_controller:
    type: FollowJointTrajectory
    action_ns: follow_joint_trajectory
    default: true
    joints:
      - shoulder_pan_joint
      - shoulder_lift_joint
      - elbow_joint
      - wrist_1_joint
      - wrist_2_joint
      - wrist_3_joint
  gripper_controller:
    type: GripperCommand
    action_ns: gripper_cmd
    default: true
    joints:
      - robotiq_85_left_knuckle_joint
```

## From the generated file to this one
1. Generated by **Auto Add** ([[moveit-setup-assistant-controllers]]): the arm controller is `ur_manipulator_controller` (in `controller_names` and as its key). MoveIt would look for `/ur_manipulator_controller/follow_joint_trajectory/`, while the robot offers `/joint_trajectory_controller/follow_joint_trajectory`. Fastest fix: rename the controller to `joint_trajectory_controller` in both places.
2. The gripper was generated as `type: FollowJointTrajectory`, `action_ns: follow_joint_trajectory`. Its server is of another type:
```bash
ros2 action info /gripper_controller/gripper_cmd -t
```
```
Action: /gripper_controller/gripper_cmd
Action clients: 0
Action servers: 1
    /gripper_controller [control_msgs/action/GripperCommand]
```
   so `type: GripperCommand`, `action_ns: gripper_cmd`.
3. Rebuild: `cd ~/ros2_ws && colcon build && source install/setup.bash`.

## Keys
| Key | Meaning |
|---|---|
| `controller_names` | the controllers MoveIt may use |
| `<name>.type` | `FollowJointTrajectory` (arm, a joint trajectory controller: [[control-jtc-commands]]) or `GripperCommand` (a gripper action controller) |
| `<name>.action_ns` | second part of the action name: `/<name>/<action_ns>` |
| `<name>.default` | this controller is the default one for its joints |
| `<name>.joints` | joints the controller moves (the gripper: only its driven joint) |
| `<name>.max_effort` | `GripperCommand` only, optional, default 0.0 (MOVEIT-V23) |

## Pitfalls
- Plan works but Execute fails: MoveIt cannot connect to a controller whose action name does not exist → compare the YAML names with `ros2 action list`.
- A `GripperCommand` server configured as `FollowJointTrajectory` (the generated default) → the gripper never moves from MoveIt.
