# Xacro files: header, properties and math, xacro CLI, processing in launch

**TL;DR** Xacro (XML macros) generates a URDF: define a value or a block once, use it many times, compute values, and include or skip parts by condition. Tools read only the expanded URDF, so run `xacro` first: by hand, or in the launch file that feeds robot_state_publisher. Syntax summary: [[core-xacro]]; macros, conditions and includes: [[urdf-xacro-macros]].

## A xacro file
```xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro" name="my_box_bot">
  <xacro:property name="body_width" value="0.1"/>
  <xacro:property name="body_lenght" value="0.1"/>   <!-- spelled like this in the course files -->
  <xacro:property name="body_height" value="0.1"/>

  <link name="base_link"></link>
  <joint name="base_link_joint" type="fixed">
    <origin rpy="0 0 0" xyz="0 0 0"/>
    <parent link="base_link"/>
    <child link="chassis"/>
  </joint>
  <link name="chassis">
    <visual>
      <geometry><box size="${body_width} ${body_lenght} ${body_height}"/></geometry>
    </visual>
    <collision>
      <geometry><box size="${body_width} ${body_lenght} ${body_height}"/></geometry>
    </collision>
  </link>
</robot>
```
- The only difference from a URDF header is `xmlns:xacro`. Extensions: `.xacro` or `.urdf.xacro`.
- `${name}` is replaced by the property value; `${…}` also evaluates Python-like expressions (`${mass*(y*y+z*z)/12}`, `${-pi/2}`). Units stay meters, radians, kilograms.
- Put properties at the top: they can be declared anywhere **before** the first `${}` that uses them, and one place to edit is the point of them.

## Expand by hand
```bash
cd ~/ros2_ws/src/my_box_bot_description/urdf
xacro box_bot.xacro > converted_box_bot_file.urdf     # or: xacro box_bot.xacro -o converted_box_bot_file.urdf
xacro box_bot.xacro robot_name:=robot1                # set a <xacro:arg>
```
The result starts with a comment "This document was autogenerated by xacro from box_bot.xacro … EDITING THIS FILE BY HAND IS NOT RECOMMENDED". Validate it with `check_urdf` ([[core-xacro]]).

## Expand in a launch file
Recommended (works for `.urdf` and `.xacro`, takes arguments):
```python
'robot_description': ParameterValue(Command(['xacro ', robot_desc_path, ' robot_name:=', robot_name_1]), value_type=str)
```
Python API, as in the course's Gazebo launch file:
```python
import xacro
# convert XACRO file into URDF
xacro_file = os.path.join(pkg_box_bot_description, 'urdf', 'box_bot.xacro')
doc = xacro.parse(open(xacro_file))
xacro.process_doc(doc)
params = {'robot_description': doc.toxml()}
```
Shorter with the same module: `xacro.process_file(xacro_file).toxml()` (no open file left behind; pass `mappings={'robot_name': 'robot1'}` for arguments). The Python API runs when the launch file is loaded; `Command` runs when the node starts.

## Pitfalls
- `name 'body_width' is not defined` → the property is used before its definition, or misspelled (the course's `body_lenght` must be spelled the same everywhere).
- Launch tries to parse the URDF as YAML → wrap `Command` in `ParameterValue(…, value_type=str)`.
- Editing the generated `.urdf` instead of the `.xacro` → lost on the next expansion.
