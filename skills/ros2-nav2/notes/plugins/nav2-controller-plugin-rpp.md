# Custom controller plugin from Regulated Pure Pursuit: interface and configure

**TL;DR** Example 3.3: a custom plugin for the **local planner** (controller), based on the **Pure Pursuit** controller written by **Steve Macenski** for Nav2 and on the paper by R. Craig Coulter, *Implementation of the Pure Pursuit Path Tracking Algorithm* (CMU-RI-TR-92-01, 1992). Instead of using the traditional DWB controller, this Pure Pursuit-based planner looks ahead along the path to generate a trajectory. The degree of path adherence depends on the **look-ahead distance**: a larger distance results in a looser following, a shorter one keeps the robot more tightly aligned with the path.

## Where the code comes from
The course says it is the [original code at commit b92561bd](https://github.com/ros-navigation/navigation2/tree/b92561bd8deba1589f5739ffffd71594adadc2f4/nav2_regulated_pure_pursuit_controller) (Jan 2021), but its files match **Galactic's RPP** (release 1.0.12) with the namespace renamed and `configure()` adapted to Humble. Full upstream files, the reference for every method not shown here: [regulated_pure_pursuit_controller.cpp (1.0.12)](https://github.com/ros-navigation/navigation2/blob/1.0.12/nav2_regulated_pure_pursuit_controller/src/regulated_pure_pursuit_controller.cpp), [.hpp (1.0.12)](https://github.com/ros-navigation/navigation2/blob/1.0.12/nav2_regulated_pure_pursuit_controller/include/nav2_regulated_pure_pursuit_controller/regulated_pure_pursuit_controller.hpp). Humble's own RPP is newer: [[nav2-rpp-controller-params]].
```bash
cd ~/ros2_ws/src/custom_nav2_controller_plugin
touch src/regulated_pure_pursuit_controller.cpp
touch include/custom_nav2_controller_plugin/regulated_pure_pursuit_controller.hpp
```

## The base class: nav2_core::Controller
This base class has several methods that need to be inside your plugin to work plug and play; all of them are **compulsory** (pure virtual in Humble); `configure()`, `activate()`, `deactivate()` and `cleanup()` are the same as in `nav2_core::GlobalPlanner` ([[nav2-planner-plugin-straight-line]]):
- `setPlan()`: called when the **global plan is updated**.
- `computeVelocityCommands()`: generates the velocity commands sent to the robot to follow the global plan generated by the global planner plugin. It returns a `geometry_msgs::msg::TwistStamped` used to move the robot; its parameters are the current robot pose, the current velocity and (Humble) the goal checker.
- `setSpeedLimit()`: also required in Humble (the course list omits it); called by the speed filter ([[nav2-speed-filter]]).

## Class interface (include/custom_nav2_controller_plugin/regulated_pure_pursuit_controller.hpp)
Header guard `CUSTOM_REGULATED_PURE_PURSUIT_CONTROLLER__HPP_`; Apache-2.0, Copyright (c) 2020 Shrijit Singh and Samsung Research America.
```cpp
namespace custom_nav2_controller_plugin
{

class RegulatedPurePursuitController : public nav2_core::Controller
{
public:
  RegulatedPurePursuitController() = default;

  ~RegulatedPurePursuitController() override = default;

  void configure(
    const rclcpp_lifecycle::LifecycleNode::WeakPtr & parent,
    std::string name, const std::shared_ptr<tf2_ros::Buffer> tf,
    const std::shared_ptr<nav2_costmap_2d::Costmap2DROS> costmap_ros) override;

  void cleanup() override;

  void activate() override;

  void deactivate() override;

  geometry_msgs::msg::TwistStamped computeVelocityCommands(
    const geometry_msgs::msg::PoseStamped & pose,
    const geometry_msgs::msg::Twist & velocity,
    nav2_core::GoalChecker * /*goal_checker*/) override;

  void setPlan(const nav_msgs::msg::Path & path) override;

  void setSpeedLimit(const double & speed_limit, const bool & percentage) override;

protected:
  nav_msgs::msg::Path transformGlobalPlan(const geometry_msgs::msg::PoseStamped & pose);

  bool transformPose(
    const std::string frame,
    const geometry_msgs::msg::PoseStamped & in_pose,
    geometry_msgs::msg::PoseStamped & out_pose) const;

  double getLookAheadDistance(const geometry_msgs::msg::Twist &);

  std::unique_ptr<geometry_msgs::msg::PointStamped> createCarrotMsg(
    const geometry_msgs::msg::PoseStamped & carrot_pose);

  bool shouldRotateToPath(
    const geometry_msgs::msg::PoseStamped & carrot_pose, double & angle_to_path);

  bool shouldRotateToGoalHeading(const geometry_msgs::msg::PoseStamped & carrot_pose);

  void rotateToHeading(
    double & linear_vel, double & angular_vel,
    const double & angle_to_path, const geometry_msgs::msg::Twist & curr_speed);

  bool isCollisionImminent(
    const geometry_msgs::msg::PoseStamped &,
    const double &, const double &);

  bool inCollision(const double & x, const double & y);

  double costAtPose(const double & x, const double & y);

  void applyConstraints(
    const double & dist_error, const double & lookahead_dist,
    const double & curvature, const geometry_msgs::msg::Twist & speed,
    const double & pose_cost, double & linear_vel, double & sign);

  geometry_msgs::msg::PoseStamped getLookAheadPoint(const double &, const nav_msgs::msg::Path &);

  double findDirectionChange(const geometry_msgs::msg::PoseStamped & pose);

  // members: tf_, plugin_name_, costmap_ros_, costmap_, logger_, clock_, one per parameter
  // (desired_linear_vel_, lookahead_dist_, …), global_plan_ and the publishers
  // global_path_pub_, carrot_pub_, carrot_arc_pub_
};

}  // namespace custom_nav2_controller_plugin
```

## Pitfalls
- The course's first version (the duplicated chapter) kept Galactic's `const std::shared_ptr<…> &` arguments in `configure()`: they do not override Humble's pure virtual and the plugin does not compile.
- `use_rotate_to_heading: true` with `allow_reversing: true` → reversing is disabled with a warning.
